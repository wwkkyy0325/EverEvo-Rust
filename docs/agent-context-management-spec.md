# 任务:为自建 agent 实现"增量上下文管理"(替代一次性压缩)

## 一、背景与目标

我的自建 agent 上下文一满就触发**一次性压缩管线**,又慢又丢信息。我不要"更大的上下文窗口",要改成**每回合后台增量维护**,让上下文水位恒定、永不触发一次性大压缩。

目标:
1. 上下文永不"满",消除一次性大压缩
2. 信息不丢:事实结构化落盘(知识库),不靠摘要记住
3. 不卡顿:压缩/抽取用便宜小模型异步做,主模型只推理

## 二、现状约束

- 本地 **llama.cpp**,小模型(如 Qwen3-VL-2B,~2GB)专门干压缩/抽取
- GPU 仅 6GB 显存,实际可用上下文窗口 **48-64K**(量化 KV)→ **不能靠大窗口,必须靠设计**
- 已有结构化知识库(llmwiki 体系,`docs/llmwiki/`),按需检索注入(RAG)
- 主模型与压缩模型可以不同(小模型便宜快)

## 三、目标架构(三层上下文)

每个回合送入主模型的 prompt 固定为以下结构:

```
[系统提示 + 目标 + 硬约束]      ← pinned,永不参与压缩
[滚动摘要(增量维护)]            ← 所有旧对话都压缩在这,~1-2K token
[最近 N 轮对话原文 verbatim]     ← 只有这段是"新的",永不压缩
[RAG/知识库检索片段]            ← 按需注入,控制在几百 token
```

每回合结束后,后台(异步/低优先级线程)执行三件事:
1. **抽取事实**:把本轮的关键事实/决定/结论提取出来,结构化写入知识库(向量化,供 RAG 检索)
2. **更新滚动摘要**:把本轮要点追加进**同一份**滚动摘要,同时压缩掉其中已无价值的细节
3. **弹出旧轮次**:把超出窗口的最老原文轮次弹出(其信息已进入摘要+知识库)

## 四、硬性规则(实现时必须遵守)

1. **永远增量更新同一份滚动摘要,禁止递归重总结**。不要用"摘要的摘要的摘要"——反复重总结 23 轮后会发生语义漂移和信息丢失。只允许 `新摘要 = 旧摘要 + 本轮要点` 这样一次性增量。
2. **最近 N 轮原文 verbatim,永不压缩**。用户消息是最高价值信息;工具输出可重取。
3. **目标与硬约束永远 pinned**,任何情况下不参与压缩/弹出。
4. **事实进知识库,不进上下文**。能结构化存盘的(结论、决定、API 用法、文件路径)一律存盘,摘要只留"叙事"。
5. **区分两类清理**:
   - 工具输出**可重取**(读文件/检索/命令结果)→ 直接丢弃,只留"调用过"的 metadata,需要时重新获取(无损省钱)
   - 对话/推理**不可重取** → 才进摘要(有损)
6. **脏活用便宜模型**:摘要/抽取用本地小模型(2-4B)异步做;主模型只做推理。绝不让主模型等压缩完成(后台线程,主循环不阻塞)。
7. **触发策略**:设定软阈值(如 70-80%),接近时后台开始压缩,而不是等 100% 才动手。

## 五、参考实现(Claude Code 的做法)

Claude Code 的机制(已验证,作为参照):
- 最近几轮保留原文 verbatim,只压缩更早的旧内容
- 大工具输出(>50K 字符)分页落盘,上下文只留 ~2KB 预览 + 文件路径
- 旧工具结果微压缩、过期 tool-use/thinking 块直接清除(前置增量清理)
- 记忆(CLAUDE.md + auto memory)在压缩后**自动从磁盘重新注入**,保证信息不丢
- 最后兜底才做一次性总结(有损,官方警告:一次会话压缩两次=任务太大)

**我们要做的改进:去掉它的"最后一次性大总结",改成每回合后台增量维护——严格更优,因为永不触发有损的大压缩。**

## 六、交付物(可验收)

实现以下组件(具体到代码,可运行):
1. **上下文管理器**:维护三层结构,暴露 `append_user_msg` / `append_assistant_msg` / `append_tool_result` 接口,内部自动触发弹窗与后台压缩
2. **滚动摘要模块**:`update_summary(old_summary, new_turns, cheap_llm)` — 一次性增量更新,受规则 1 约束
3. **事实抽取模块**:`extract_facts(turn) -> List[Fact]` — 从回合中抽结构化事实,写入知识库向量索引
4. **后台任务调度**:异步/线程池,低优先级,主循环不阻塞;压缩失败不影响对答
5. **窗口弹出策略**:`evict_oldest(until_under_limit)` — 弹出后保证 `系统+摘要+原文+RAG ≤ 窗口×软阈值`
6. **工具输出处理**:分页落盘 + 2KB 预览 + metadata,可重取即丢(规则 5)
7. **与知识库(RAG)对接**:注入接口 `inject_retrieved(chunks)`,控制注入量
8. **压测/验收**:长对话跑通,观察上下文水位恒定、无一次性大压缩、关键事实可召回

## 七、技术备注

- llama.cpp 启动压缩模型:`llama-cli -m <小模型> --no-display-prompt -p <压缩prompt>` 或 `llama-server` HTTP 接口
- 提示词格式:抽取/摘要用明确的 JSON 输出或结构化标签,便于解析
- 摘要 prompt 可参考:`Retain: [当前任务,关键决策,正在修改的文件] / Completed: [已完成] / Next: [下一步]`
